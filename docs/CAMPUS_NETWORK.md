# 校园网络专项排查 (DNS 封锁 / 严重污染)

> 一句话: **代理不需要你配置任何 DNS 服务器**, 且自带**抗 DNS 污染**。
> 它自己会解析上游真实 IP, 并用 TLS 证书验证筛掉污染假 IP; 不用手动干预。
> 只有极端情况 (所有手段都失败) 才需要手动填一个 IP (见文末)。

## 零、严重 DNS 污染下怎么还能用 (核心机制)

DNS 污染的本质是: 你问"xlb.810086.com 的 IP", 却得到一个**假 IP** (黑洞、内网地址、或
攻击者的服务器)。传统防污染靠"多 DNS 交叉对比", 但这不够——你的校园网可能把
**所有** DNS 查询都污染了。

本工具用的是**更强的验证**: 拿到候选 IP 后, 对它做 **TLS 握手 + 系统 CA 证书验证 + 域名匹配**。
真实服务器持有 Let's Encrypt 给 `xlb.810086.com` 签发的证书; 污染假 IP **不可能**有这张证书。
于是假 IP 被自动淘汰, 代理回退到下一层解析。

```
拿到候选 IP
  ├─ 是私有/保留地址 (10.x / 192.168.x / 127.x / 0.x ...) ? -> 剔除 (污染典型特征)
  ├─ TLS 握手 + 证书验证 xlb.810086.com ?
  │     ✓ 通过  -> 确认真服务器, 就用它 (短路返回)
  │     ✗ 失败  -> 淘汰, 继续下一个候选
  └─ 全部候选都不通过 -> 退回"TCP 可达"的并告警 (unverified)
```

实测 (模拟严重污染: 缓存/系统 DNS 都返回假 IP):

```
候选 192.168.99.99 (cached)    -> 剔除 (私有/保留地址, 疑似污染)
候选 10.1.1.1      (system-dns) -> 剔除 (私有/保留地址, 疑似污染)
候选 8.134.221.255 (udp-dns)    -> CA-verified (issuer CN=YR1)   <- 真服务器
RESULT: 污染被绕过 ✅
```

## 一、为什么代理要"碰 DNS"

代理伪装成 `xlb.810086.com`，它需要知道**真实服务器 IP** 才能转发。
但 hosts 已把 `xlb.810086.com` 指向 127.0.0.1（指向代理自己）：

```
if 代理用系统解析器问 "xlb.810086.com 的 IP"
   → 系统查 hosts → 127.0.0.1
   → 代理连到自己 → 死循环
```

所以代理必须**绕过 hosts** 拿真实 IP。实现为多层解析链 + 证书验证（ **懒执行**, 命中即停）:

```
[1] 手动       rules/upstream_ip.txt / --upstream-ip   (最优先, 信任)
[2] 缓存       backup/upstream_ip.json                 (上次成功的 IP)
[3] 系统/校内 DNS  socket.getaddrinfo                  (校园网的校内 DNS, 常可用 + 快)
[4] 公共 UDP DNS  223.5.5.5 / 119.29 / 8.8.8.8       (校园网常封或伪造)
[5] DoH (443)  dns.alidns.com / doh.pub / CF           (固定IP直连+SNI, 加密抗污染)
[6] 内置已知 IP  8.134.221.255                          (历史结果, 最后兜底)
```

**每一层拿到的候选都先过"保留地址过滤 + TLS 证书验证"**, 第一个真正验证通过的即采用。
启动实测 ~3.5s (缓存命中)。全失败也不退出, 仅告警并继续监听。

## 二、"三个 DNS 我全都解析失败" 是怎么回事

你测的（223.5.5.5 / 119.29.29.29 / 8.8.8.8）都是**校外公共 DNS**。
校园网普遍**只允许校内 DNS，对外部 UDP/53 直接丢包或伪造** → 三个必然全失败。

**但这不影响使用**，因为第 [3] 层（系统/校内 DNS）通常能用，且第 [5] 层 DoH 走 443 也常通。
即使这些都被污染, 证书验证也会把假 IP 筛掉, 最后第 [6] 层/手动 IP 兜底。

> 旧版本缺陷: 三个 DNS 全失败就**直接退出**, 代理不启动 → 客户端"未连接"。
> 现已修复: 多层兜底 + 证书抗污染 + 全失败也不退出。

## 三、诊断: 一条命令看清是哪一层的问题

```
py -3 scripts\netcheck.py
```

输出六步 (每步带判定):

```
[1] hosts/系统解析    -> 应 127.0.0.1 (劫持生效)
[2] 公共 UDP DNS      -> 可能 FAIL (校园网正常现象)
[3] 系统/校内 DNS      -> 通常可用
[4] DoH (固定IP直连)   -> 一般可用
[5] 候选 IP 验证       -> 保留地址过滤 + TLS 证书, 标出哪一个是"已验证真服务器"
[6] 本机代理 443       -> 代理是否在跑
```

## 四、按诊断结果处置

| netcheck 结果 | 含义 | 怎么做 |
|---|---|---|
| [5] 有 `CA-verified` 的 IP | 找到真服务器 | 双击 `start.bat`，无需配置 |
| [5] 全部被剔除/无 verified | 污染严重或上游证书变更 | 在 `rules/upstream_ip.txt` 写真实 IP（见下） |
| [5] 全 BLOCKED/TIMEOUT | 校园网封了出站 443 | 与本工具无关，换网络/热点 |
| [6] NOT LISTENING | 代理没跑 | 双击 `start.bat` |

## 五、手动指定 IP (极端情况)

`rules/upstream_ip.txt` 默认全是注释 = 自动解析。若污染严重且自动解析全失败:

```
# 打开 rules/upstream_ip.txt, 取消注释并填真实 IP:
8.134.221.255
```

保存后双击 `start.bat`（脚本把它作为 `XLB_UPSTREAM_IP` 传给代理）。或命令行:

```bash
py -3 src\hijack_proxy.py --upstream-ip 8.134.221.255
set XLB_UPSTREAM_IP=8.134.221.255   &&   双击 start.bat   （等效）
```

怎么查真实 IP:
- 在**能正常上网**的手机/电脑上 `ping xlb.810086.com`
- 或看代理日志里历史成功记录 `backup/upstream_ip.json`
- 注意: 手动 IP 也会被证书验证; IP 写错会被剔除并告警。

## 六、缓存机制

代理每次成功解析（通过证书验证）都会写 `backup/upstream_ip.json`。
下次启动优先用缓存并**重新验证证书** —— 即使当天 DNS 被彻底污染, 只要 IP 未变就能直接跑。
若 IP 变了 (证书验证失败), 自动回退到其它层解析。

## 七、其他校园网相关情况

### hosts 改了但还是连不上

1. 确认 hosts 生效: `Resolve-DnsName xlb.810086.com` 应返回 127.0.0.1
2. 客户端要**完全重启** (Electron 多进程): `end.bat` → `start.bat`
3. 客户端自动更新会覆盖 asar 补丁 → `start.bat` 会自动重打

### 校园网强制用自己的 DNS / 做流量劫持

若校园网把 443 流量也做透明劫持 (中间人), 真实服务器证书会不匹配 → 我们的证书验证会识别;
但此时代理→上游的连接也会受影响。判断方法: `netcheck.py` 第 [5] 步无 verified 且
手边手机热点下能解析——说明校园网在拦截。处置: 用手机热点, 或找校内可直达的路径。

### 出站 443 被防火墙拦

```
Test-NetConnection 8.134.221.255 -Port 443
```

False = 校园网封了出站 443。代理无法回源, **换网络或开手机热点** 才能用。
（这不是劫持工具的问题: 连官方客户端本身也连不上。）
